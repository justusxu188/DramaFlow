# 短剧投流素材批量生产系统设计

## 目标

把上传的短剧源片自动转化为多组“AI 前贴 + 高光剪辑”投流素材。系统核心价值不是生成单条视频，而是复用一次剧情理解结果，批量派生差异化故事线、高光、脚本、前贴和最终成片，并保留完整来源与版本关系。

## 核心判断

### 剧情理解不能只理解台词

只理解台词会丢失：

- 人物外观与身份关系
- 无台词动作、表情和冲突
- 场景、镜头、视觉奇观和情绪强度
- 原片高光的准确起止时间
- 前贴结尾与高光开头的画面、动作、台词衔接条件

因此采用分层多模态理解：

1. **通用主干：MediaKit 剧情故事线分析**
   - 输入单集或多集视频。
   - 输出片段标题、摘要、对白、时间码、精彩度评分和高光故事线。
   - 真人短剧、动画漫剧均作为首选主干。
2. **真人短剧增强：MediaKit 剧本还原**
   - 输出场景、人物、对白、情绪、声音、镜头和视觉描述。
   - 官方能力不适用于动画，因此不能作为漫剧统一主干。
3. **自定义补充：Seed 2.0 Lite 多模态分析**
   - 对故事线关键帧、候选高光和高光前 N 秒做定向理解。
   - 补齐人物视觉锚点、开头动作、首句台词、镜头运动、情绪和可衔接条件。

最终统一为内部 `DramaKnowledge`，下游不直接依赖任何供应商原始 JSON。

## 推荐生产流程

### 1. 素材接入与标准化

- 分集或整剧上传至 TOS。
- 读取媒体元数据，校验格式、时长、分辨率、音轨和集数顺序。
- 整剧文件先生成逻辑章节；超过 MediaKit 单任务限制时按集或时间窗口分批。

### 2. 多模态剧情理解

- 调用故事线分析生成 `storyline_clips` 与 `storyline_highlights`。
- 真人短剧并行调用剧本还原。
- 将人物、关系、事件、冲突、情绪、场景、对白、镜头与时间码归一化。
- 保存供应商原始结果到 TOS，保存标准化索引到 MySQL。

### 3. 爽点故事线提炼

使用 Doubao Seed 2.1 Pro 对 `DramaKnowledge` 做结构化推理，输出 3-8 条候选：

- 故事线标题与一句话卖点
- 受众：男频 / 女频 / 泛人群
- 爽点类型：逆袭、打脸、身份揭露、金手指、复仇、救赎等
- 情绪曲线与核心冲突
- 证据片段 ID 和时间码
- 适合的前贴关系类型、钩子类型和高光策略
- 新颖度、可视化程度、剧情相关度和合规风险评分

模型只能基于证据片段提炼事实；允许创作的内容必须明确标记为“延展设定”。

### 4. 批量高光剪辑

对每条选中的爽点故事线调用：

`POST /api/v1/tools/generate-highlights-microdrama`

每条故事线可生成多个版本：

- `Sequential`：顺剪，适合剧情回顾。
- `Mixed`：混剪，适合营销高光。
- 自定义开场、主体和结尾 Prompt。
- 开启 `enable_storyboard`，保留源视频、时间码、OCR 和评分。
- 每个版本完成后立即转存 TOS，避免 24 小时结果地址失效。

当前代码中的 `createHighlight()` 错误调用了 `/tools/concat-video`，必须替换。

### 5. 高光开头理解

从每个高光版本提取前 3-8 秒，使用 Seed 2.0 Lite 输出：

- 首帧和首个动作
- 首句完整台词
- 当前人物、地点、事件与情绪
- 前贴结尾必须满足的承接条件
- 推荐过渡：硬切、动作匹配、台词接力、时间跳转、声桥、白闪
- 禁止冲突：人物身份不一致、时间线矛盾、动作无法连续

该结果称为 `TransitionAnchor`，是生成“丝滑过渡”脚本的必要输入。

### 6. AI 前贴脚本批量生成

Doubao Seed 2.1 Pro 输入：

- 选中的爽点故事线
- 对应原片证据
- `TransitionAnchor`
- 用户控制参数
- 可选趋势灵感
- 合规与时长约束

系统预设下拉项：

- 钩子范式：反常台词、超自然猎奇、身份反差、生死危机、自定义。
- 关系类型：剧情强关联、剧情延展、强引流、自定义。
- 叙事结构：高潮前置、完整前史、倒叙回扣、单点奇观、社会议题借势。
- 时长：3-8 秒、12-15 秒、15-22 秒、22-44 秒、自定义。
- 受众：男频、女频、泛人群。
- 视觉风格：3D 动画、仿真人、古风玄幻、现代写实、自定义。
- 过渡方式：硬切、时间线、动作匹配、台词接力、声桥、白闪。
- 灵感来源：仅剧情、趋势辅助、指定灵感、自定义要求。

每个脚本必须返回结构化口播、镜头、动作、视觉提示、音效、过渡和事实引用。默认一次生成 3 个脚本，不直接生成 20 个低质量版本。

### 7. AI 前贴视频生成

- Seedance 2.0 Fast：预览和大规模探索。
- Seedance 2.0 Mini：入选脚本的较高质量成片。
- 角色参考图、风格参考、首尾帧和镜头级 Prompt 均版本化。
- 多镜头长前贴按镜头生成后再拼接；不得假设单次视频任务能稳定完成 22-44 秒完整叙事。

### 8. 合成与质量门禁

使用 MediaKit 拼接“前贴 + 高光”，生成前执行自动检查：

- 时长、比例、编码和音量
- 黑帧、静帧、字幕遮挡和音画不同步
- 前贴结尾与高光开头的语义、人物、动作和声音连续性
- 剧情事实一致性与合规词检查

质量通过后转存 TOS，并记录完整谱系：

`源片 -> 故事线 -> 高光 -> 过渡锚点 -> 脚本 -> 前贴 -> 成片`

## 批量策略

系统不做无上限笛卡尔积。推荐默认矩阵：

- 3 条爽点故事线
- 每条 2 个高光版本
- 每个高光 3 个脚本
- 每个脚本先生成 1 个 Fast 预览
- 人工或自动评分选出 4-6 个，再用 Mini 精制

理论候选 18 条，实际高成本精制控制在 4-6 条。所有中间结果可缓存复用，修改前贴不重跑剧情理解和高光。

## 趋势灵感系统

趋势灵感是独立子系统，不阻塞 MVP：

1. 定时获取抖音、小红书、微博的公开或授权趋势源。
2. 保存来源、时间、热度、原文摘要和可用期限。
3. 分类为爆梗、社会话题、视觉奇观、叙事模板。
4. 用 Seed 2.0 Lite / 2.1 Pro 评估与当前短剧的题材、人物、冲突和受众匹配度。
5. 只把 Top N 灵感作为创作约束输入，并保留来源引用。

不建议直接绕过平台限制抓取页面。优先采用官方接口、授权数据源或公开聚合源。

## 数据与任务架构

### MySQL

新增主要实体：

- `AnalysisRun`：供应商任务、版本和状态。
- `DramaKnowledge`：标准化整剧理解。
- `StoryBeat`：带来源时间码的剧情片段。
- `StoryArc`：爽点故事线。
- `HighlightVariant`：高光版本与 storyboard。
- `TransitionAnchor`：高光开头衔接条件。
- `InspirationItem`：趋势灵感。
- `ScriptVariant`：结构化前贴脚本。
- `RenderVariant`：Seedance 前贴任务。
- `Composition`：最终合成与谱系。
- `QualityEvaluation`：自动与人工评分。

### TOS

保存源视频、供应商原始 JSON、关键帧、临时剪辑、前贴、最终成片和质检报告。

### Worker

Next.js 仅负责 API 与控制面。独立 Worker：

- 领取持久化 Job。
- 调用供应商异步 API。
- 处理回调或轮询。
- 下载短效产物并转存 TOS。
- 重试、超时、取消和幂等。

## 当前实现差距

1. `analysis` 使用通用 Ark 直接理解视频，没有 MediaKit 故事线主干。
2. `script` 使用硬编码“林晚”剧情，没有读取真实分析结果。
3. `createHighlight` 实际调用拼接接口。
4. 高光阶段只做场景切分，未调用短剧高光智剪。
5. 只处理一个 `video_url`，未支持 `video_urls`、`mixvideo_info` 和 storyboard。
6. 任务进度是固定模拟值，没有 Worker 持久化状态。
7. 供应商短效 URL 没有统一转存 TOS。
8. 当前七阶段是线性 UI，不支持故事线、高光、脚本和渲染的分叉谱系。
9. 本地 JSON 降级只覆盖项目与素材，不适合生产任务编排。

## MVP 边界

第一版必须完成：

- TOS 源片接入
- MediaKit 故事线分析
- 真人短剧可选剧本还原
- 爽点故事线提炼
- MediaKit 多高光生成
- 高光前 N 秒分析
- 结构化前贴脚本生成
- Seedance Fast 预览
- 前贴与高光拼接
- 全链路持久化、重试、转存和人工确认

第二版再做：

- 趋势灵感定时采集
- Seedance Mini 精制矩阵
- 投放数据回传与自动优选
- 模型 Prompt 自动迭代

## 成功指标

- 上传到首批候选成片耗时
- 单剧可用成片数量
- 人均日处理剧目数
- 人工一次通过率
- 前贴与高光衔接通过率
- 单条成片成本
- 失败重试率
- 创意重复度
- 接入投放后：3 秒播放率、CTR、CVR、PVR 和消耗
